# 研究迁移、对比与已有笔记核查

## 研究启发要可操作

从论文中提取值得借用的操作，而不是只写“结合扩散”“加入信息论”“进一步优化”。对值得展开的设想说明：

| 项目 | 要回答的问题 |
|---|---|
| 来源机制 | 论文中哪项操作提供启发，出处在哪里？ |
| 目标瓶颈 | 用户当前明确的研究问题是什么，二者如何对应？ |
| 适用前提 | 输入、数据、监督与计算预算是否满足，哪些条件有差异？ |
| 改动位置 | 改数据构造、编码、掩码、目标、检索还是评分？ |
| 最小验证 | 什么低成本对照能区分目标机制与替代解释？ |
| 失败标准 | 哪种观察说明该迁移不值得继续？ |

只对确有价值的方向展开；不固定输出 idea 数量。没有用户研究背景时可以描述一般适用条件，不能凭空假定项目或收益。

区分“可复用机制”“新组合设想”和“待证实的新研究贡献”。已知组件组合可能有价值，但其新颖性、必要性和效果分别需要比较和验证。

## 复现规划

根据用户要复现的部分整理数据及划分、环境、预处理、模块、目标函数、训练／推理配置、评测脚本、种子和缺失细节。用户只要理解时不生成完整工程计划。

有代码则记录核实过的实现与论文差异；缺失配置标为未确认，必要的实现假设显式列出。不要编造运行命令、仓库入口或硬件需求。数值推导检查和小例子验证不等于复现论文结果。

## 已有笔记核查

1. 识别哪些是摘录、翻译、作者主张、用户观点或后续回答；无法判断时保留不确定性。
2. 有原文时逐项核对关键公式、模块关系、评测协议和争议结论；无原文时只检验内部一致性与一般逻辑。
3. 输出：原表述 → 问题类型 → 依据 → 建议修订 → 剩余核查。
4. 保留有价值的疑问，不自动认同也不无依据否定；不因为“看起来合理”就把待核查改成已解决。

常见类型：术语误译、重复背景、作者观点被写成事实、从局部结果过度推广、未注明来源的简答、旧图片路径失效、把提出的问题当成已证实缺陷。

优先生成修订建议或单独核查笔记；用户要求直接更新时才修改对应原笔记，并保留其个人观点与未解决问题。

## 指定论文对比

按同一问题框架整理：目标与未见对象、核心操作、训练信号、推理成本、所用信息、结果及协议、证据边界、对当前研究的用途。

比较技术差异时指出“相对哪个方法，多做或改变了哪一步”；不能仅按论文自称的贡献数排名。综述应围绕共同问题与方法分歧综合，避免把单篇摘要简单拼接。

只有用户要求建设长期方法库或问题库时才维护跨论文记录；普通阅读保留在本篇笔记里即可，不自动扩大为完整学术管理系统。
