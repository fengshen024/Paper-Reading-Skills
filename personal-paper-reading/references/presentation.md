# 图文呈现与理解自检

## 默认 Markdown

正文用中文，英文标题与技术术语保留必要原词。首次解释术语时给准确中文含义；例如 LLM 是大语言模型，recall 是召回率，不能沿用错误机翻。

用“先结论／直觉，再机制，再必要形式化细节”的讲法。保留公式和关键操作，减少长段近似翻译与重复摘要。用户指定沿用七栏目时按其要求组织。

以 Markdown 为主稿时，优先用普通表格、短伪代码和本地图像保证直接阅读；不要让大量只供 HTML 渲染器消费的 JSON 块占据正文。结构化块仅在用户的阅读器支持或其呈现收益明确时使用。

## 图表按用途选择

- 原图用于保留作者架构与实验信息；流程图用于解释输入输出和依赖，表格用于比较证据。没有理解收益时不用画图。
- 不要求全量提图，也不强制按原编号重排讲解。保留原编号、来源与语境，优先靠近相关解释。
- 图前说明要看哪个部分和它回答的问题，图后解释关键箭头、坐标或观察。不能让一张截图替代关键机制解释。
- 查看实际提取图，确认图例、坐标、标签和相关图注可读且没有误裁；失败时可以使用带页码的整页图或说明缺失。
- 不固定缩到 800px 或强制 JPEG／base64；保证公式和小字可读，按交付需要选格式。
- 自绘图标为解释性重绘，未测的示意图不能用视觉长度暗示定量收益。

笔记内部优先使用可迁移的相对图片路径，例如 `paper-slug.assets/fig-2.png`；聊天中展示本地图片时遵循环境的绝对路径要求。检查文件实际存在，不继承旧笔记中的其他机器路径。

## 每篇完整笔记的理解自检

默认给少量论文特定题，通常 2–3 道，难度适合已展示的阅读背景。优先从以下角度选题：

- **机制重建**：用自己的话走一遍输入到输出；去掉某一步会改变什么？
- **证据边界**：哪个实验支持主张，是否排除更大预算、更多信息等解释？
- **条件迁移**：换数据、假设或推理设置，哪部分可能失效，如何最小验证？

避免只问作者、年份、指标数值或定义背诵。问题能从本篇笔记已解释的材料推理回答；如果本来就是开放研究问题，明确没有唯一答案。

先呈现全部题目，再用 Markdown 的 `<details>` 区放参考答案、关键推理和来源。不支持折叠的阅读器使用独立“参考答案”小节，保证答案仍可读。

自检不是对用户知识状态的评估记录。只有用户真实作答后才判断其理解；默认不暂停等待答案。用户明确要求互动带读时，一次问一个问题，依据回答给提示，再决定是否提供答案。

## 可选 HTML

只有用户请求可视化页面或双格式交付时生成；Markdown 仍为可编辑主稿。将同一内容、数字和限定条件转换到页面，不在两份材料里独立编写相互矛盾的结论。

优先使用随包携带、由 05 项目适配的 `scripts/render-reading.cjs` 和 `assets/reading.css`；命令与块格式见 [工具使用](tools.md)，可从 [呈现示例](../examples/reading-demo.md) 选取适合的部分。已支持公式、原图嵌入、实验问题表和折叠自检，不必重新搭建渲染器。模板是起点，不能用教学示例内容填充真实论文笔记。

重要文字、关键表格、公式和静态图在离线或脚本不可用时仍可读。仅在交互能揭示实际分支、状态或反馈时加入交互。公式渲染依赖不可用时说明限制，不能宣称已经完整渲染。

页面需实际检查窄屏溢出、公式、原图、导航与折叠答案；工具可用时渲染并视觉检查，不把 HTML 文件生成成功当成显示正确。默认不启动固定端口服务，也不因没有 HTML 环境阻塞 Markdown 阅读。
