# 证据与实验核查

## 以问题组织实验

对主要主张寻找最直接的证据：

| 主张 | 需要寻找的证据与条件 |
|---|---|
| 系统性能更好 | 相同任务、划分、候选集与指标下的关键对比；额外数据或预算的差异 |
| 某模块导致收益 | 隔离该模块的消融／替代设计及配套控制；整套系统胜出不能单独归因 |
| 更有效率 | 可比硬件、批量、规模和任务下的耗时／吞吐／内存／预算；分清训练与推理 |
| 更鲁棒或泛化更强 | 与主张相符的噪声、偏移、新实体／关系或跨域设置，不能泛化出未测范围 |
| 理论保证 | 明确假设、定理结论、证明覆盖对象及与实际模型的差别 |
| 数据集或评测有效 | 构建规则、标注与审核、覆盖偏差、划分和指标的有效性 |

不为每篇论文机械展开所有维度；集中检查会影响核心结论的事项。

## 关键数值的最小上下文

保留数据集／划分、指标方向、比较对象、双方数值、单位与来源。区分绝对差值和相对提升：

```text
教学示例：MRR 从 0.250 到 0.260，绝对增加 0.010，相对增加 4%。
```

多个指标变化不一致时逐项报告。不能因 MRR 上升就写“整体全面提升”，也不能把没有方差的微小差值写成统计显著。

表格存在排版歧义时核对表头、脚注及页面图像；小数／百分数、平均方式、数据规模和效率分母不明时保留疑问。

同一论文的摘要、主表、细粒度表和图例若出现不一致，记录各处原值和位置，不能自行解释成“不同配置”或擅自统一。区分字符抽取错误、可见的示例矛盾与尚未核实的数据/代码问题；示例错误不自动证明整个方法或数据集错误。

## 公平性与归因

按实际相关性检查：划分与信息可见性、负采样／候选集合、指标实现、backbone、额外预训练数据、参数量、训练预算、调参资源、推理预算、后处理。

区分“设置不同”与“不公平”：不同设置可能是在比较不同研究问题，关键是作者是否据此提出不成立的优势结论。强基线未匹配预算可以限制归因，但不能仅凭模块更多判定收益无效。

基线数字来自引用而非统一复现时检查协议是否一致。没有得到相关设置时写“当前无法确认是否可比”，而不是直接下结论。

## 消融与稳定性

- 移除模块时还改变了哪些超参、预算、训练策略或数据？能否隔离贡献？
- 替代方法、负对照和成本对照是否能区分“特定机制有效”和“额外容量／信息有效”？
- 多个训练种子与多个评测采样种子回答不同问题。只改变评测采样不能证明训练稳定。
- 方差、置信区间与显著性检验缺失时，说明证据范围；不能自行假定显著或不显著。
- 全系统结果、单模块效果、交互效应和机制解释分别判断，避免混用。

## 对质疑也做证据约束

采用以下表达：

```text
观察：来源中报告了什么，或当前确实缺少什么。
影响：它使哪一种结论仍存在替代解释。
验证：什么最小检查、对照或补充材料能消除疑问。
```

缺少正文时不能写“论文没有消融”；应写“当前材料未包含消融”。没有某项证据通常表示结论受限，不自动表示方法错误。

审查“首次”“唯一可行”“根本解决”等词时，明确主张范围，检查直接相关前作或作者提供的依据；未做领域检索时不得替作者确认首次性。

## 多篇论文

先对齐任务与协议，再组织共同问题、机制分歧和证据差异。不可比的分数分别列出，不能直接排名。检索或引文核验仅在比较需要时开展，并记录实际查到的来源；不强制论文数量、数据库数量或固定引用阈值。
