# 研究导向论文精读

帮助读者回答：论文解决什么具体问题，关键设计如何改变计算或信息流，证据实际支持什么，以及哪些内容值得带入自己的研究。

## 个人偏好与适用边界

- **已确认的输出偏好**：中文 Markdown 为主，按需加入原图、流程图、公式和表格；每篇完整笔记末尾附少量理解自检题，参考答案折叠呈现。局部问答无需重新生成整篇笔记或附题。
- **从样例推断的讲解偏好**：重视问题动机、模型架构、个人疑问、思考启发；尤其关注模块实际操作、训练与推理区别、公式含义、实验公平性和可迁移价值。用户后续要求优先。
- **当前研究背景线索**：少样本／归纳知识图谱推理、相似关系、子图与边掩码，及条件扩散、Gumbel-Softmax、信息论的可能用途。仅在相关时使用，不能将历史兴趣视为所有任务的固定目标。
- 先理解作者试图完成的事情，再评价方法与证据。不要将普通精读变成通篇挑错，也不要把作者的贡献宣称直接改写为事实。
- 保留用户旧笔记与原有观点；可以提出带依据的修订。没有原文时，不能用既有笔记“证明”笔记本身正确。

## 按请求选择深度

| 请求 | 执行方式 | 交付重点 |
|---|---|---|
| “快速介绍／值不值得读／五分钟” | 速览 | 问题、核心机制、关键证据与阅读建议；标明覆盖范围 |
| “读这篇／精读／做阅读笔记” | 默认完整阅读 | 核心方法、训练与推理、主要实验、相关附录、局限与启发 |
| “这个公式／模块怎么理解” | 局部深读 | 只展开该问题及必要上下文，不强制整篇模板 |
| “我的笔记有错吗” | 笔记核查 | 有原文则交叉核对；仅有笔记则检查内部逻辑并列出待核查项 |
| “比较这些论文” | 指定论文对比 | 对齐任务、机制和评测条件，再比较贡献与适用范围 |
| “能借鉴什么／准备复现” | 研究迁移／复现规划 | 适配条件、最小验证、缺失细节；规划与实际运行分开 |

把分层阅读作为内部工作方式，不要求用户逐遍确认。已要求精读时，速览后的价值判断不能成为自行停止的理由。理论、数据集、系统和综述论文应调整重点，不能硬套神经网络架构。

## 阅读流程

### 1. 确认材料与任务

确认论文身份、版本及已获得的正文、附录、代码或笔记。标题不能唯一定位时询问必要信息；已能确定的任务直接推进。论文正文优先，附录补足细节，官方代码用于澄清实现；博客与旧笔记只作为辅助材料。

说明材料覆盖范围：完整正文、部分章节、仅摘要或仅笔记。无法取得全文时，完成可依据当前材料完成的分析，标明缺少什么，不能宣称已完整精读。没有执行的检索、代码检查、数值验证或实验不能写成已完成。

### 2. 先建立整条逻辑

先看摘要、引言、主图、主结果与结论，形成可修正的框架：

```text
任务与输入输出 → 现有瓶颈 → 核心设计动作 → 信息流或目标如何改变
             → 什么实验检验它 → 得到的结论及适用边界
```

区分“旧方法的不足”与“本文仍存在的限制”。贡献要说明相对哪一种方法增加或改变了什么。阅读优先级依据与研究目标的相关性、技术内容和证据，不能由作者名气、引用数或 venue 代替。

### 3. 拆清机制，解决关键疑问

完整笔记必须让读者能描述一次从输入到输出的过程。读方法、公式、图注、算法及支撑核心细节的附录；训练与推理分别说明。不要停留在模块名称罗列。

按需读取 [机制与公式讲解](references/method-reading.md)，解释输入、操作、输出、设计原因、代价与证据。代码相关问题读取实际实现并给出文件／行号；代码未获得时只给明确标记的示意伪代码。

### 4. 把实验证据接到主张上

围绕主要贡献组织“问题—设置—对照—指标—结果—解释”，保留关键对比数值和实验条件。需要展开通用实验设计或归因问题时，再读取 [证据与实验核查](references/evidence-review.md)。

知识图谱／KGQA／少样本关系推理论文优先读取 [知识图谱专项协议](references/kg-protocol.md)，不重复加载通用核查文档中已覆盖的事项。其他领域不加载或套用这些规则。

对局限的评价应落到具体证据或缺失信息上。提出“观察到什么 → 为什么影响判断 → 什么检查能区分解释”，不要用泛泛的“创新不足”“缺少实验”代替分析。

### 5. 整理个人问题与研究启发

整理用户已提出的问题，区分已核实、部分回答、待核查和迁移假设。以来源解释问题如何解决，不要无依据地写“都可以”“已解决”。原问题未解决时，保留它并指出缺少的证据。

需要研究迁移、论文对比、复现规划或笔记核查时读取 [研究迁移与笔记核查](references/research-use.md)。启发应指出具体可借用操作、适用前提及最小验证，不要求每篇论文都有正向启发。

### 6. 生成与核对笔记

完整笔记按 [个人笔记模板](references/note-template.md) 组织；这是一套可裁剪的默认结构，不能机械填满无关栏目。默认合并重复的背景和不足，补足实验与证据。

原图就近解释，保留编号与来源，检查图例和图注可读。自检题通常 2–3 道，围绕该论文的机制、证据边界或迁移条件，参考答案放入 `<details>`；不能编写用户的回答或假称用户已经掌握。需要进一步的图文编排或 HTML 时，再读 [呈现与理解自检](references/presentation.md)。

需要 PDF 文本／页面裁剪、Markdown 转离线 HTML 或 HTML 检查时，读取 [工具使用](references/tools.md)，调用随 skill 携带的脚本。已复用并适配原项目的渲染器、样式与通用测试，另携带原项目的 HTML 校验器；不要在已有工具适用时重复手写实现。可运行的 [呈现示例](examples/reading-demo.md) 包含流程、公式、实验问题表和自检答案。

### 7. 按需保存到 Notion

用户明确要求上传时，读取 [Notion 上传与授权](references/notion-upload.md)，使用 `scripts/upload-to-notion.cjs` 导入已核对的 Markdown 和配套图片。每篇笔记创建独立页面，可选父页面下、数据库中，或通过 PAT 在工作区顶层创建私人页面。只添加此能力或只要求阅读，不等于要求立即上传。先进行本地 `--dry-run`；实际上传需要已指定的保存模式和用户本地配置的凭证。目标或授权缺失时，完成本地准备并说明配置步骤。

脚本可独立于 MCP 运行；不读取 Codex 保存的 OAuth 凭证。上传成功后返回 Notion URL；部分失败如实报告回执状态，不能把已创建但尚未写完的页面称为成功。重复运行以本地回执避免创建副本，本版只新建或显式另建版本，不覆盖已有笔记。

### 8. 完成后清理中间文件

笔记、配图和所需的 HTML/Notion 上传均核对完成后，按 [工具使用中的清理说明](references/tools.md) 调用 `scripts/cleanup-reading.cjs`。先预览，再对本次明确使用的 PDF 提取目录执行 `--apply`；符合已授权范围的常规中间文件清理无需再次询问。失败或仍待核查时保留对应中间材料。保留笔记、配图、原始 PDF、来源记录、配置、测试报告和 Notion 上传回执；回执用于防重复上传，不能当垃圾删除。

## 来源与判断的表达

- 给关键事实、公式、性能结论和批评附最窄来源，例如 `[原文 §3.2, Eq.4]`、`[原文 Table 2]`、`[附录 B]`、`[代码 src/model.py:80]`。
- 在内容相关处区分 **作者主张**、**实验观察**、**解释／推断**、**用户判断**、**待核查**。标签按需使用，不必每句话加标记。
- 只有笔记时使用 `[旧笔记：论文名／栏目]`，并说明“原文未核实”；已读到原文但作者没报告才写“原文未报告”。不能把未读到的内容判为作者遗漏。
- “首次”“唯一”“证明”“显著”“SOTA”需要相称的证据与范围。新颖性未做前作核查时写成作者的贡献主张；没有统计检验时不要暗示统计显著。
- 公式推导、玩具例子、自绘流程图和原文数据各自说明来源属性。合成数值必须标为教学示例。

## 文件与工具

生成笔记时使用用户指定位置；未指定时放在当前工作区 `notes/<paper-slug>.md`，图放在同目录配套的 `<paper-slug>.assets/`，按需创建。优先维护一篇权威笔记；未要求更新时避免覆盖已有文件。

### 减少串行工具往返

- 全文文本提取一次，后续在本地按 PDF 页码或章节分段读取，避免因输出截断重复读取全文。正文、图注已足够回答的内容无需截图。
- 先决定哪些图有解释价值，再一次渲染目标页（默认 `--scale 2`）。逐页查看时记录该页所有目标图的 bbox；坐标为 PDF 点，屏幕像素需要除以 scale，不能凭屏幕显示尺寸猜坐标。
- 把这些 bbox 写入一份 `--clips` JSON，用一条命令在同一目录 `--append --no-text` 批量裁图，再在同一轮检查输出；工具支持多图输入时合并发送。不要逐图执行“裁一张、读一张、再试坐标”。
- 仅对确有裁切问题的图补裁一轮；仍难以准确定位时使用带页码的较宽区域／整页图并说明，避免为排版反复试裁。整页不可读时保留待核查项，不能以减少调用为由略过关键证据。
- 已查看且未变化的图不重复读。复制最终图时沿用已验证文件；依赖只在需要时探测一次，缺失时按工具文档安装，不轮流试多个图像库。

使用当前环境可用的 PDF、检索或代码工具，不依赖某位作者的绝对路径、固定端口、特定模型服务或另一个收集来的 skill。图表、公式或表格提取不可靠时查看页面渲染；核实不了就明确保留不确定性。

可以复制、改造或组合适合阅读任务的既有脚本、渲染器与模板。复用部分随包携带，保留许可证、出处和必要归属声明；当前清单见 [THIRD_PARTY.md](THIRD_PARTY.md)。按实际功能选择实现，不为了复用而继承与本任务无关的强制流程。

生成新笔记不需要再次确认。研究建议不等于启动训练、改代码、维护长期知识库或更新系统记忆；这些行为遵循用户实际授权。可选功能不会成为完成普通阅读的门槛。

## 交付前检查

- 深度符合请求；完整精读覆盖主方法、主要实验及核心主张依赖的附录。
- 能说明核心操作以及它为何针对所述瓶颈，训练与推理路径清楚。
- 关键数值、公式、图注与实际读到的材料一致；比较保留协议、单位与分母。
- 作者主张、观察和推断可分辨；旧笔记和缺少来源的疑问未被升级为事实。
- 个人问题得到回答或有明确待核查项；启发具有适用条件，未凭空增加研究目标。
- 完整笔记附少量自检题及分离的参考答案；插图和本地链接可用。

交付时先给用户需要的结论，再给笔记路径与必要的未核实范围。不要在聊天里重复整篇笔记。
